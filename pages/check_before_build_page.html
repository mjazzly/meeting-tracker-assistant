Does this exist? A request through the library

What happens between someone describing a thing they want built and a decision to reuse, extend or brief it. The library is an index of what has already been built, one line each: when to use it, its inputs, its output, its limits and what it was tested on. The assistant is an AI model given a written set of rules; a tool is a small program the model calls to do a step; a gate is a point where the run stops and a person answers before anything is built. Every entry here was built on invented data.

The assistantThe judgement steps: what the request asks, whether the limits cover it, what is still blank
Passes it onSends the request as written to the search. Two requests in one message are searched as two. It does not answer from memory of what the library holds.
Reads
  • Match: one entry fits. Go on to the limits.
  • Possible: two fit about equally. Ask which; never pick.
  • New: nothing fits. Ask for the brief.
ComparesReads the entry's limits line against the request, clause by clause. Inside the limits: returns the entry and stops. A clause outside them (a system it does not connect to, a step it declines): stops to ask.
Fills what the request answersOnly the fields the request itself settles. Every other field stays blank, and each blank becomes a numbered question. It never fills a field with what it supposes the requester meant.
AppliesTakes each answer as given and writes it into the field. A field with no one to ask is marked "assumed" and said so in the reply.

Before any of this is trusted

Six requests with expected verdicts written before the first run, checked twice: the search as code, the skill as a model reading it.

1. Cases firstThree ordinary requests that should match one entry; one that fits two entries that chain; one that nothing covers; one that matches an entry but asks for a step its limits decline.
›
2. One commandnode library/library_test.js runs the six through the same search the tools use and checks every entry carries a use it when, inputs, output, limits and tested on line.
›
3. Checked, not readEach verdict and each name is compared with the expected one. A miss is named (the verdict given, the entry it chose). Result on 25 Oct 2026: six of six.
›
4. The skill, run blindEach request in a fresh conversation, the model given only the skill and the tools. Four versions; on the last, Haiku 5.5 six of six, twice, and Opus 5.5 six of six.

Reading the page

A person acts: asks, chooses, answers, decides.
The assistant judges: the steps that need reading and sense.
A tool runs: the steps that must happen the same way every time.
A gate stops the run until a person answers. Three in all.
